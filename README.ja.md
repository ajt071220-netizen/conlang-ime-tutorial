## I. SVG で字形を作る

まず必要なのはベクトル形式の SVG です。文字は SVG コード自体で描きます。SVG（Scalable Vector Graphics）は、世界の主流入力メソッドで標準的に使われる形式です。コードで記述した図形は、ブラウザや OS が画面密度に合わせてベクトル描画するため、拡大しても PNG のようにぼやけず、常にシャープです。描画も制御しやすく、既存フォントファイルに依存しないため、入力メソッドの標準になっています。本チュートリアルでは、主に SVG の図形とパスで文字パターンを描きます。パスでほぼ何でも描けますが、図形ごとに固有の構文もあります。パスだけで描くと面倒な図形もあるので、準備と、専用要素で描いた方が簡単な図形から紹介します。これが SVG 構文の入門部分です。

### (1) キャンバスのサイズと座標

![キャンバスのサイズと座標](images/02.png)

キャンバスの設定は、字形を描く前の最も基本的な準備です。上図のとおり、最初の準備は XML 名前空間（`xmlns` とその後ろの長い文字列）、`width` と `height`、`viewBox` の三つです。重要なのは後二者で、最初のものはあまり気にしなくて構いません。`width` と `height` はキャンバスの幅と高さです。入力メソッド制作では **1024×1024** が推奨サイズで、上図のとおりです。これが業界の事実上の標準です。`viewBox` は座標系を定義します。4 つの数字は、先頭の二つの `0` が原点 `(0, 0)`、続く二つの `1024` が x 軸・y 軸方向の幅と高さを表します。字形を描くときは、幅・高さと viewBox の x・y 範囲を 1:1 に保ってください。幅が 1024 なら x も 1024、高さについても同様です。このソフトでは、座標が分からないときは右側のキャンバスにマウスを置くと、現在位置の座標が表示されます。

### (2) 矩形（`rect`）

![矩形1](images/04.png) ![矩形2](images/14.png)

矩形1では、`rect` が矩形、`x` と `y` が左上角の座標、`width` と `height` が幅と高さを表します。矩形2では、`fill` が内部の塗りつぶし色です。`fill` は閉じた図形でよく使いますが、線を描くときにも必要になることがあります（後述）。`rx` と `ry` は少し難しい概念で、角丸の横・縦の大きさを表します。角丸は楕円の一部だと考え、`rx` と `ry` がその楕円の軸です。角の位置を中心に楕円を描き、元の角を切り取って接するようにする、とイメージするとよいでしょう。これは後述のパスの曲線と同様、練習と感覚で身につく部分です。

### (3) 円（`circle`）

![円](images/06.png)

円のコードでは、`circle` が円、`cx` と `cy` が中心、`r` が半径です。

### (4) 楕円（`ellipse`）

![楕円](images/08.png)

楕円のコードは円とほぼ同じです。`ellipse` が楕円で、違うのは `rx` と `ry` がそれぞれ横・縦の半径（長い方が長軸、短い方が短軸）になる点です。設計次第です。

### (5) 直線（`line`）

![直線1](images/10.png) ![直線2](images/12.png) ![矩形3](images/16.png)

直線1では、`(x1, y1)` と `(x2, y2)` が線の始点と終点です。`stroke` は線の色、`stroke-width` は太さ、`stroke-linecap` は両端の形です。1枚目では `butt`（SVG の既定：端が平ら）を使い、2枚目の `round` は丸い端です。この二つが実用的です。矩形3では、`stroke` と `stroke-width` で輪郭を強調できます。

### (6) 角のつなぎ（`stroke-linejoin`）

![角1](images/18.png) ![角2](images/20.png) ![角3](images/22.png)

三図はそれぞれ丸・尖・斜めの角で、`round`、`miter`、`bevel` です。折れ線で特に重要です。折れ線では `stroke` と `stroke-width` にも注意し、`fill="none"` を付けてください。付けないと、始点と終点を結んで塗りつぶした閉じた図形にしようとすることがあります。

### (7) パス（`path`）

![パス1](images/24.png) ![パス2](images/26.png) ![パス3](images/28.png)

パスは SVG で最も重要な形式で、ほぼあらゆる模様を描けます。1枚目で `M` は *move to*（指定座標へペンを移動して始点にする。例：`(100, 100)`）、`L` は *line to*（その点まで直線を引く）です。2枚目は曲線、パスで最も重要な手法である三次ベジェ曲線です。`M` は同じで、`C` が二つの制御点を表します。制御点は曲線上にはなく、曲線を曲げる「磁石」だと考えてください。制御点が曲がる部分に近いほど鋭く、遠いほどなだらかになります。三次ベジェには二つの制御点（例：`(430, 430)` と `(974, 430)`）と終点があり、始点は `M` です。3枚目は二次ベジェで、先頭が `Q`、制御点は一つ、最後が終点です。制御点は難しいので、自分で練習してください。

ここまでが SVG の基礎です。第2段階に入る前に：スクリーンショットの書式を厳密に守ってください。大文字・小文字、各行の `<` と `/>`、英文の直ダブルクォート `""` は必須です。特に1行目の宣言の両端の `<` と `>` を確認してください。1文字欠けても右側のプレビューが止まることがあります。上記の要素は組み合わせ可能です。パスで直線を引き、隣に `circle` で円を描く、など。図形コードは先頭の宣言と閉じタグ `</svg>` の間に書きます。宣言と `</svg>` の両方を完全に保ってください。記号が一つ欠けてもプレビューが止まり、エラーになります。

## II. TTF/OTF フォントファイルの作成

![フォント制作1](images/30.png)

上図のようにソフトを開いたら、まず文書／フォント名を好きなように付けます（後で使います）。初期設定を直したら、上部の **フォント管理** から **単一 SVG を追加** をクリックし、SVG コードエディタで保存したファイルを選びます。アップロード後、Unicode 私用領域（PUA）の符号位置が自動割り当てされます。Unicode は、世界のあらゆる言語・記号の文字に一意の番号を振る国際的な文字符号化標準で、文字化けを防ぎ、データの交換と互換を実現します。入力メソッドの根幹技術の一つです。私用領域は公式の意味が決まっていない予約ブロックで、利用者・団体・フォントベンダーが自由に割り当てます。

アップロード後は、字形下の左右サイドベアリング（**LSB** / **RSB**）と字幅（advance width）を調整します。**1024×1024 UPM** でのラテン文字の目安：

- `i`、`j` のような細い小文字：約 **220–320**
- `f`、`t`、`r` などやや広いもの：約 **280–400**
- `a`、`n`、`o`、`e` など通常の小文字：約 **480–620**
- `w`、`m` など広い小文字：約 **750–920**
- 通常の大文字：約 **580–720**
- `W`、`M` など特に広い大文字：約 **800–1000**

経験則として、片側の空白は字幅のおよそ **8%–18%** です。PUA は順に振られるので、自分のアルファベット順でアップロードするのがおすすめです。その後 **生成／エクスポート** で **フォントを生成** をクリックし、TTF を作ります。

## III. Keyman Developer と Keyman for Windows のダウンロードと使い方

ここが開発の本番であり、最も重要な工程です。この入力メソッド開発エンジン上で、作ったフォントと組み合わせて完成させます。まず公式サイトから両方をダウンロードします：

- [Keyman Developer をダウンロード](https://keyman.com/developer/download)
- [Keyman for Windows をダウンロード](https://downloads.keyman.com/windows/stable/18.0.249/keyman-18.0.249.exe)

**注意：** 直リンクが失敗する場合は、[Keyman for Windows 公式ダウンロードページ](https://keyman.com/windows/download) から手動でダウンロードしてください。

インストール後、Keyman Developer を初めて開き、**New Project** をクリックし、キーボードの種類で **Keyman keyboard** を選び、名前と説明を入力します。どちらも人工言語名のラテン転写で構いません。**OK** で作成します。ツリーで **Keyman keyboard** を選び、言語名の `.kmn` ファイルを開きます。

左上の **View** から **Character Font** を選び、先ほど作ったフォント名（**.ttf なし**）を検索し、**Apply** のあと **OK** をクリックします。「サイズは 0 と 0 の間でなければならない」のようなエラーが出ることがあります。その場合は気にせず、**Apply** のあと **OK** でダイアログが出たら、フォント選択ごと閉じてください。オンスクリーンキーボードのフォントは後述の場所で直します。

次に **Layout** タブを開き、**Design** から **Code** に切り替え、14行付近の `group(main) using keys` の下（15行目から）に規則を書きます。各行の形式は次のとおりです：

```text
+ [K_A] > U+E000
```

（`+` のあと、`]` のあと、`>` の前後にスペース）。`[K_A]` は物理キー A（Shift なしで小文字 a）です。数字や文字キーに自分の文字の Unicode を対応させれば十分です。実機キーボードより後述のオンスクリーンキーボードを主に使います。`+` と `>` は必須で、スペースも上記どおりです。各キーと Unicode の対応を正しく保ち、`[K_B]`、`[K_C]` なども使えます。アンダースコアを忘れないでください。

アルファベット数ぶんの対応ができたら、Layout 下の **On-Screen** を開き、**Fill from layout** をクリックします。これでマッピングはコピーされますが、キーキャップに自作字形が表示されるわけではありません。On-Screen の **Code** を開き、8行付近の次を探します：

```xml
<encoding name="unicode" fontname="Arial" fontsize="-12">
```

`fontname` を `Arial` から自分のフォント名に変え（引用符はそのまま）、`fontsize` を **-16** にします（引用符とマイナスはそのまま、数字だけ変更）。これでキーキャップにフォントの文字が出ます。**Design** に戻るとキーが空白に見えることがあります。**Text** に空白のように見えるのも、私用領域文字がデザイナで描画されないためで問題ありません。

終わったら **Build** を開き、**File actions** の **Compile Keyboard** をクリックします。**Messages** に緑の行で **built successfully** と出れば成功です。次にプロジェクトのタブから **Packaging** を開き、`.kps` ファイルを開いてキーボードを選び、**Languages** の **Add** をクリックします。ダイアログの最初の **Tag** に最大3文字の言語タグを入れて保存し、**File → Save** します。再び **Build** から **File actions** の **Compile Package** をクリックし、**Built successfully** を確認します。

次に **Keyman for Windows** を開き **Start Keyman** をクリックします。ウィンドウが閉じたら、時計付近のトレイ（上向き矢印）に Keyman があるか確認します。あれば起動済みです。Keyman Developer に戻り、`.kps` の **Build** で **Install** をクリックします。完了後、入力切替で新しいキーボードを選び、トレイの Keyman から **On Screen Keyboard** を開きます。キーキャップに自分の文字が載った仮想キーボードが出れば、入力を始められます。
